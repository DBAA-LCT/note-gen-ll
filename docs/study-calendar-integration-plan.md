# Study Calendar 融入 NoteGen 的实施方案

## 目标

`D:\data\study-calendar` 是完整功能原型，用来定义学习管理能力和交互预期；它不是要被原样嵌入 NoteGen 的第二套应用。

最终形态应沿用 NoteGen 现有三栏结构：

- 左侧：学习入口、今日任务摘要、快捷筛选和待复习提醒。
- 中间：完整的学习工作区，与普通笔记一样通过标签页切换。
- 右侧：复用现有 AI 对话/Agent，承担规划访谈、复盘、调度建议和知识问答。

## 产品结构

### 1. 学习中心作为系统标签页

新增一种 NoteGen 系统标签页 `learning`，支持以下内部视图：

- 今日：今日任务、里程碑、记忆卡片、学习热力图。
- 专注：计时器、当前任务、暂停/完成记录；轨道模式作为可选视觉模式。
- 日程：日/周/月/年/议程视图、搜索、拖拽调整、目标和里程碑叠加。
- 目标：左侧目标列表，中间目标详情、阶段、任务和进度。
- 报告：日报、周报、月报及趋势，不再使用独立应用式大弹窗。
- 复习：知识条目、复习队列、测试记录、墨墨/Markji 同步状态。

学习侧栏只做导航和摘要，不承载完整页面，避免控件拥挤以及“侧栏里又套一个应用”。

### 2. 笔记是学习内容的主体

- 学习资料继续使用 NoteGen 文件、标签、编辑器和搜索。
- 学习目标、任务、日程、复习状态使用结构化 SQLite 数据。
- 知识条目引用笔记路径、标题或内容片段，不复制一套独立知识库。
- RAG/向量库只索引笔记与知识内容，不作为任务、日程、进度的事实数据库。
- 日报、周报、月报最终生成普通 Markdown 笔记，同时保留用于统计的结构化数据。

### 3. AI 复用 NoteGen 现有能力

- 不迁移原型里的模型设置、AI SDK、独立聊天界面。
- 规划访谈、每日复盘、计划调整、知识测验都放在 NoteGen 右侧 AI 面板。
- AI 返回结构化建议，先展示变更预览，用户确认后再写入目标、任务和日程。
- AI 使用现有模型、API Key、提示词和 RAG 配置。
- 墨墨 Token 等第三方凭证沿用 NoteGen 当前 API Key 的保存与读取方式，不保留 Web/桌面两套特殊逻辑。

## 原型能力映射

| 原型模块 | NoteGen 中的落点 | 处理方式 |
| --- | --- | --- |
| Home / Today | 学习系统标签页的“今日” | 保留任务卡、里程碑、热力图；去掉独立顶栏 |
| Today Study / Focus | 中间专注视图 | 保留计时和记录；轨道模式可切换，标准模式默认 |
| Calendar | 中间完整日程视图 | 迁移多视图和交互，接入学习任务与里程碑 |
| Study Plans / Goals | 中间目标主从视图 | 复用 NoteGen 样式、标签页与右侧 AI |
| Daily Review Interview | 右侧 AI Agent + 报告笔记 | 用工具调用读写学习数据 |
| Period Report Center | 报告视图 + Markdown 笔记 | 统计结构化数据，结果落入笔记 |
| Knowledge Panel | NoteGen 文件/标签/RAG + 复习元数据 | 不建立平行文件树和内容仓库 |
| Daily Knowledge Quiz | 学习工作区“复习” + 右侧 AI | 复用笔记内容生成题目并记录掌握度 |
| Maimemo / Markji | 设置中的学习连接器 + 复习视图 | 使用统一凭证保存机制和同步网关 |
| Settings | NoteGen 现有设置窗口 | 只增加“学习与连接器”分区 |
| Electron / Capacitor / sql.js | 不迁移 | 使用 NoteGen 的 Next.js、Tauri、SQLite 与 Store |

## 数据边界

### 继续使用 NoteGen

- 文件与 Markdown 内容
- 标签、搜索、编辑器标签页
- SQLite/Tauri 数据访问
- AI 模型与 API Key 配置
- Chat/Agent、RAG 和向量索引
- 桌面与移动端现有布局

### 从原型选择性迁移

- 学习目标、阶段、任务和日程领域模型
- 每日任务生成规则与计划调整规则
- 专注计时和学习记录
- 日/周/月/年/议程日历交互
- 每日复盘和周期报告聚合逻辑
- 知识复习调度、测验记录与掌握度
- 墨墨/Markji 的 API 映射与同步逻辑

### 不迁移

- 原型自己的导航、页面外壳和移动底栏
- 原型自己的数据库、文件仓库和向量库
- 原型自己的 AI 设置、模型调用层和凭证策略
- Electron、Capacitor 以及独立应用生命周期代码

## 实施顺序

1. **融合外壳**：增加 `learning` 系统标签页和中间学习工作区；把当前侧栏降级为摘要与入口。
2. **核心闭环**：迁移今日、目标、专注、完成记录和日报，让“计划 → 学习 → 复盘”跑通。
3. **完整日程**：迁移多视图日历，将任务、目标阶段、里程碑和自定义事件统一展示。
4. **知识与复习**：把 NoteGen 笔记接入知识条目、复习队列、测验和掌握度。
5. **外部连接器**：完善墨墨和 Markji，同步配置进入现有设置。
6. **AI Agent 化**：为规划、复盘、调整、报告和测验提供可确认的结构化工具调用。
7. **移动端适配**：在现有移动布局中提供今日、日程和专注的核心流程，而不是复制原型导航。

## 验收标准

- 从任意笔记可直接创建学习任务，并回链到原笔记。
- 学习中心在中间工作区打开，不遮挡或替代 NoteGen 主导航。
- 今日任务、目标、日程、专注记录、复盘和报告共享同一份结构化数据。
- 日历能展示并编辑任务、里程碑和自定义日程。
- AI 使用 NoteGen 已配置模型，并且所有写操作可预览、可确认。
- 报告可作为普通笔记继续编辑、搜索和引用。
- 墨墨/Markji 凭证与现有 API Key 使用一致的保存策略。
- Web 预览缺少 Tauri 能力时明确降级，不在模块加载阶段调用桌面 API 导致页面崩溃。
